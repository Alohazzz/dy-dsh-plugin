# 云效议题原型功能对照

核对对象为 Nezha 云效页、任务启动和回写链路。下表记录代码行为和首版模拟界面的差距，供设计复核。

| 环节 | Nezha 行为 | 当前原型与移植边界 |
| --- | --- | --- |
| 连接与项目 | 令牌、组织、云效项目、当前用户、刷新和重新连接。本地目标开发项目另选 | 原型固定云效项目，只在启动时选工作区。两个项目的用途需要分别呈现 |
| 列表 | 分类、我负责的、状态与版本多选、产品、计划完成时间、编号或标题查询、加载更多。状态与版本加载失败可重试 | 原型只有类型、单状态和关键词筛选。高级筛选属于 Y1 后续范围 |
| 行信息 | 编号、标题、类别、云效状态、方案状态、产品、优先级、负责人、创建日、计划完成日、逾期、原议题链接 | 原型缺产品、优先级、日期、逾期及源链接 |
| 行操作 | 未占用议题可以直接开始、讨论或加计划；直接执行任务可定位；方案中的议题按状态提供回答、继续讨论、开始或继续执行、查看等动作；已入交付计划时显示计划名。多选支持联合讨论和加计划，已导入项限制勾选 | 原型只能查看详情或开始。直接执行应能返回绑定会话。专用讨论入口及交付计划按既有取舍记录 |
| 启动前 | 拉取正文、提示图片数量，可打开原议题、填写发起人补充。详情失败可用补充继续。需求可直接执行或先澄清，澄清支持逐条、批量、界面三种方式。缺陷走诊断取证。选择启用的 Agent 及适用权限 | 原型只选择工作区。DSH 需映射可用 Agent、权限和提问能力，保留类型分流与上下文 |
| 执行中 | 确认后创建绑定议题的待启动任务，准备正文与图片，再启动；入口防重复创建，失败可定位任务 | 原型确认后立即生成模拟交付稿，缺绑定会话、准备中、运行中与失败恢复 |
| 回写 | 编辑开发向和测试向评论，可重新生成，发布中限制重复操作。可选评分评论，评分字段写入失败可单独补写。记录回写时间与评论 ID | 原型支持编辑和成功反馈，缺生成、发布中、失败、重试和回执。评分按 Y5 后置 |
| 状态 | 云效工作项状态、讨论方案状态、本地执行任务状态各有来源。入交付计划和移出计划会按业务规则回写云效字段。工作项完结有独立后端能力 | 原型自由切换四种模拟状态。DSH 的 Y6 应使用该议题工作流，确认目标并回查，回写评论和更改状态分别反馈 |

## 第二版复核

三个布局共享开工、会话、回写和流转弹窗。云效状态显示在详情标题旁，执行状态显示在会话字段中。模拟参数仅在页面内生效。

| 操作 | 可核对的结果 |
| --- | --- |
| 开工并返回 | 可选择工作区、Agent、权限，填写补充。需求可选择提问方式，缺陷使用诊断取证。原文读取失败时可补充说明继续。 |
| 重开会话 | 议题保留会话编号。准备失败可在原会话重试，随后可答复澄清、模拟完成执行并生成交付草稿。 |
| 发布中断 | 模拟第二条评论失败，第一条保留回执和发布时间。重试仅处理未发布的评论。 |
| 状态回查 | 按模拟工作流选择目标，提交后回查。超时保留上次核实状态，重复回查仅查询模拟云端。 |

工作区、Agent、权限和可选目标状态均使用样例数据，正式接入时由 DSH 与云效提供。

## 第三版复核

补充云效项目、我负责的、状态／产品／版本多选、计划完成日期及目标开发项目。状态筛选展示已选值；行内流转后按回查结果重新筛选。各示例议题提供产品、负责人、截止日期和逾期提示。

页面工具栏可创建模拟计划，列表支持单条和勾选多条加入目标开发项目的计划。已入计划显示归属。参考 Nezha 的 AddToPlanDialog，待开发议题仅补归属，其余更新为待开发并记录负责人及开始日期；议题原定截止日期保留。原型中的源分支只记录名称。

## 源码定位

路径相对 Nezha 仓库根目录。

- 页面组合、筛选和加载：`src/components/yunxiao/YunxiaoView.tsx`、`YunxiaoFilterBar.tsx`、`useYunxiaoFilters.ts`。
- 行操作与条件：`src/components/yunxiao/YunxiaoIssueList.tsx`、`src/utils/yunxiaoPlanState.ts`。
- 启动：`src/components/yunxiao/DirectLaunchDialog.tsx`、`src/App.tsx` 中的直接执行处理函数。
- 回写：`src/components/yunxiao/YunxiaoWritebackDialog.tsx`、`src/App.tsx` 中的 `handleWritebackYunxiao` 和 `handleRetryWritebackScoreField`。
- 云效状态与交付计划：`src-tauri/src/yunxiao.rs`、`src-tauri/src/delivery_plan.rs`、`src/components/delivery-plan/PlanPanel.tsx`。

## 第四版实机对照

在正在运行的 Nezha 云效页勾选两条议题后，批量区同时显示已选数量、发起讨论和添加到计划。进入添加到计划时，当前 HIS 项目提示暂无进行中的计划。取消后勾选保留。清除勾选后打开直接开始，实机展示原文拉取、发起人补充、需求澄清和 Agent 选择。验证止于开工确认前。

DSH 三种布局均保留单条和多选讨论入口。入口展示目标开发项目与按勾选顺序排列的议题，可以返回继续选择。讨论后续工作流待定。批量加到计划也沿用勾选顺序。

在 DSH 原型用样例数据走通状态筛选、两条议题加入计划、开工、完成执行、开发向评论成功而测试向评论失败、单条重试，以及待开发流转到开发中后首次回查超时、再次回查成功。

| 环节 | 仍需处理的差异 |
| --- | --- |
| 筛选与列表 | 云效选项加载失败重试、分页加载、刷新及重新连接。行内还缺优先级、创建日和原议题链接。 |
| 加到计划 | Nezha 的 AddToPlanDialog 区分成功、已加入、失败和未处理，仅重试可重试项。原型只有成功路径。计划详情中的移出及反向回写尚未覆盖。 |
| 开工 | Nezha 行内可直接开工或定位已绑定任务。原型通过详情开工；正文与图片准备、Agent 和权限仍为模拟。 |
| 回写 | 原型已覆盖两条评论及失败重试。Nezha 的评分评论、评分字段独立补写属于后置范围。 |
| 状态流转 | 本次实机列表通过加计划触发待开发；完结还有云效侧及特定任务入口。DSH 独立状态菜单按样例工作流演示，正式接入需核对目标工作项可用流转。 |
