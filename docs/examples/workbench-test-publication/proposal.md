# 执行方案 · 云效新增发布只包含测试

## 目标与范围

工作台从新稿和旧稿预览并发布测试评论。已有评论和回执可追溯。测试发布遇到远端响应丢失时，能够回查已收录评论并恢复回执。评分随 #5 接入。

## 实施依据与已确认决策

依据 [调研报告 v1](research.md)。模拟确认 D1 选择「保留旧记录，读取时映射」。旧文件已有固定位置和回执，可在读取时识别测试，并完整保留历史。该决定允许新确认的测试保存在独立的版本化记录中。

## 修改范围与实施步骤

1. **解析（R1、R2）**。在 `src/yunxiao.mjs` 提取共享的章节解析逻辑。提供测试段读取入口，接受标准和旧测试标题，校验非空及重复测试章节。当前双段解析入口供旧调用方继续使用。
2. **宿主（R1、R2、R3）**。在 `src/workflow.ts` 让工作台按回写项类型提交。读取顺序为新版测试记录、旧发布记录的测试项、当前交付稿测试段。旧记录已有测试回执时直接展示该回执。旧记录仅有已发布方法时，将该回执作为历史展示，并允许确认当前测试。旧记录中已经确认但仍待发布的测试沿用其确认正文和原回写标记。
3. **预览（R1）**。更新 `src/contracts.ts`、`src/host.ts` 和 `src/panel.tsx`，测试作为唯一可编辑和提交的回写项。首次发布前校验确认版本与正文，发布后显示回执。历史记录进入独立的只读区域。
4. **恢复（R3）**。通过原评论发布接口发送规范化测试正文。明确失败后允许重试，远端结果不明时先回查同一标记。找到评论后补存回执，回查仍无结果时显示待核实。

## 验收与回归

| 用例 | 前置与步骤 | 预期及证据 |
| --- | --- | --- |
| T1（R1）新稿独立发布 | 为模拟议题生成仅含测试的稿件，预览后编辑测试正文并确认。 | 仅发送一条评论，内容等于最终确认正文。记录模拟请求和回执。 |
| T2（R2）旧稿与回执 | 分别打开旧双段稿、有方法回执的旧记录、已有测试回执的旧记录。 | 旧标题可读，只能发布测试。原记录可查，已有测试回执时远端不新增评论。 |
| T3（R3）远端成功后响应丢失 | 用模拟客户端在写入成功后丢弃响应，重启宿主并重试。 | 按原标记回查出评论并补存回执，远端写入计数为 1。 |
| T4 集成验证 | 在隔离 Desktop profile 安装候选包。为授权云效测试议题打开旧交付稿，编辑测试正文并确认发布，重启后复查。 | 云效仅出现一条测试评论，评论 ID 与宿主回执一致。 |

## 风险与异常处理

旧记录存在已确认测试正文时保留其原文。若回执无正文或与议题归属不符，标记待核实并展示可查证据。T4 依赖候选安装包和具有评论权限的测试账号，缺少条件时记录待验证。
