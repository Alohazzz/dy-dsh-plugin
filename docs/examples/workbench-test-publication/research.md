# 调研报告 · 云效新增发布只包含测试

## 业务背景与范围

工作台用户在执行完成后将测试材料发到云效。当前预览要求填写开发向和测试向两段。目标是本批允许测试独立发布，已发布的历史评论可追溯，评分随 #5 接入。

## 业务规则与例外

- R1：新发布只提交最终确认的测试正文。修改方法和方案偏差留在执行小结。
- R2：新版和旧版测试标题都可读。已发评论正文和回执可查，旧记录里尚未发布的方法正文跳过。
- R3：测试发布可独立重试。云效已收录而本地回执缺失时，先回查并恢复回执。

## 现状与证据

- `src/yunxiao.mjs:92` 兼容旧测试标题，但解析结果固定要求两段都有正文。
- `src/workflow.ts:160` 优先返回存量发布记录。当前正文和回执按位置对应。改变列数时需要保留历史位置含义。
- `src/workflow.ts:176` 固定要求两个发布项，`src/panel.tsx:731` 按位置命名预览。只删界面的开发向输入会导致宿主拒绝请求。
- `src/yunxiao.mjs:121` 按云效组织、议题和规范化正文计算回写标记。重试前回查已有评论，因此升级时保留已确认的测试正文与标题即可复用回查能力。

## 历史结论核对

旧回写流程验证了逐项回执和重启补发，相关测试在 `test/workflow.test.mjs:415`。沿用「有回执的项不重发」及远端回查规则。旧版两项同时发布的前提已变更，首次发布只需要测试。

## 影响范围

涉及交付稿解析、宿主预览和发布、发布记录读取、工作台预览和回归测试。旧发布记录的兼容处理会影响升级恢复。评分计算及字段写入由 #5 处理。

## 需求逐项可行性

| 需求 | 证据与候选做法 | 可行性结论 |
| --- | --- | --- |
| R1 测试独立发布 | 解析已能识别测试标题，宿主和界面的双项限制可以一并改为按类型处理。 | 可实现 |
| R2 旧稿和历史回执 | 旧顺序固定，位置 0 是方法、位置 1 是测试，可按位置读取。可继续读取旧文件，或者一次性迁移并保留备份。 | 满足指定前提后可实现，待确认旧记录处理方式 |

## 待确认问题与结论

**D1（R2）**。升级后应保留旧发布记录，还是一次性转换成新版记录？

- 推荐保留原记录。读取时按原位置解释正文与回执，新确认的测试写入带类型的新记录。存量审计可直接核对原文件，升级失败时恢复简单。代价是保留两种读取路径。
- 可选一次性转换，转换前保存原记录并按版本标记去重。后续只读新格式，但要增加转换失败、重复升级和备份恢复测试。

**当前状态**。D1 待确认。测试回查已有实现和可替换客户端用于设计回归，真实云效验证列入实施验收。D1 确认并复核后生成执行方案。
