# Nezha → DeepSeek Harness 移植清单

这份清单用于评估哪些 Nezha 能力值得移植到 DeepSeek Harness（DSH）插件。每项可独立标注为必迁、后置或舍弃。涉及流程联动的项目在表内注明。

迁移量为初步估计。低表示主要复用技能、文件约定或读取逻辑；中表示需要接入 API、Git 或项目配置；高表示需要维护跨会话、跨仓库或跨系统的流程状态。估计来自 Nezha 实现和操作手册，待 DSH 插件原型验证。

## 云效议题

| 编号 | 候选能力 | 迁移范围与取舍 | 迁移量 |
| --- | --- | --- | --- |
| Y1 | 读取议题与筛选议题池 | 按编号读取正文和图片，按需补充项目、版本、状态和计划完成时间筛选 | 中 |
| Y2 | 单议题直接开工 | 把议题作为需求交给 DSH，沿用 `yunxiao-issue-execution` 的执行约定，提交时关联议题编号 | 低 |
| Y3 | 先讨论方案再开工 | 澄清需求，形成 `plan.md`，定稿后按方案执行 | 低 |
| Y4 | 执行结果回写 | 从 `discussion.md` 提取交付结论，预览后发表为云效评论，可与议题完结分开启用 | 中 |
| Y5 | 价值评分 | 沿用 `issue-value-scoring`，保留评分原文，按需写入云效自定义字段 | 中 |
| Y6 | 议题状态流转与完结 | 从 DSH 推进议题状态并核对结果，明确由谁判定业务完成 | 中 |
| Y7 | 开发中补录新议题 | 发现新问题时生成草稿，在云效立项并绑定后续待办 | 中 |

## 交付计划与分支合并

| 编号 | 候选能力 | 迁移范围与取舍 | 迁移量 |
| --- | --- | --- | --- |
| P1 | 按交付计划组织议题 | 将一批议题绑定到交付分支和完成日期，加入或移出时同步云效排期、负责人和状态 | 高 |
| P2 | 多议题拆单与依赖调度 | 定稿后按议题生成待办，读取 `deps.json`，在前置任务完成后放行后续任务 | 高 |
| M1 | 单仓发起合并请求 | 从当前分支选择目标分支，在 Codeup 创建合并请求（MR） | 中 |
| M2 | 多仓批量提 MR | 找出同一交付分支涉及的子仓库，分别向各仓库的目标分支提 MR | 高 |
| M3 | 待审 MR 查询与本地拉取 | 集中查看待审 MR，按仓库筛选并拉取选中的 MR | 中 |
| M4 | AI 合并审查与报告 | 按公司审查规则检查 MR 差异，生成报告，按需将结论发到 MR 评论 | 中 |
| M5 | 批准、合并与结果核对 | 在 DSH 发起批准、合并或关闭，核对 Codeup 结果。同步本地交付计划时与 P1 联动 | 中，联动 P1 后为高 |
| M6 | 合并冲突处理 | 在本地解决并验证源分支冲突，再继续原 MR | 高 |

## 公司技能管理

| 编号 | 候选能力 | 迁移范围与取舍 | 迁移量 |
| --- | --- | --- | --- |
| S1 | 在 DSH 使用现有公司技能 | 从指定目录发现 `SKILL.md`，验证首批技能的脚本、路径和工具依赖 | 低起，视技能而定 |
| S2 | 公司 SkillHub 技能源同步 | 配置本地或 Git 技能源，查询同步状态并拉取更新 | 中 |
| S3 | 按项目或 Agent 分发技能 | 查询安装情况，按需安装或卸载，检查失效链接 | 中 |
| S4 | 技能配套数据维护 | 检查技能依赖的数据状态，执行备份或构建 | 中 |

## 首批建议

- **验证议题执行闭环**可选 S1、Y1（仅按编号读取）、Y2、Y4。验收用一条测试议题，从输入云效编号开始，按公司规范执行并把结果写回原议题。
- **减少多仓漏提 MR**可优先评估 M2。
- **减少人工审查耗时**可优先评估 M3 和 M4，最终批准和合并可继续在 Codeup 网页操作。
