# 研发工作台档案与回写验收记录

2026 年 11 月 20 日在 Windows 验证 GitHub #26–#34 的工作区改动。候选包由 `npm pack` 生成，包版本为 `0.2.1`，仅用于本机验收。DSH Desktop 随附 CLI 版本为 `0.2.2-rc.3`。浏览器验证使用隔离的 `web` profile 和 Chrome。

## 验收证据

| 议题 | 验证场景与结果 |
| --- | --- |
| #26 | 从实际包加载文档 Skill、六类模板、档案入口和清单初值。校验拒绝缺字段、空正文、重复和错序，保留代码围栏中的示例标题。旧稿可预览测试段，新增发布只有测试正文。 |
| #27 | 打开旧计划时不创建文件。A 启动调研后在 B 建计划，A 的后台结果写回 A。删除或损坏索引后可从清单重建，文件冲突保留原内容并提示路径。 |
| #28 | 首次选择的成员单独记录。重试批量排期时保留成功项。移出和重新加入各有记录。计划报告可追溯初始成员、延期和移出原因。 |
| #29 | 调研使用独立报告。关键问题未解决时只保存报告，答疑后保存报告和可送审方案。跨计划按议题、模块或关键词检索，保留历史替代关系。 |
| #30 | 送审、退回和批准引用对应方案版本。退回后新增方案版本，旧审核记录可查。执行入口核对当前获批版本。 |
| #31 | 实际临时 Git 仓库中的两个议题各自关联预期 SHA，错误关联被拒绝，重复归档不重复登记。移出后重新加入会建立新的执行会话。 |
| #32 | 测试评论失败可重试。远端已成功而本地档案冲突时，修复后只补存回执。评分及依据随 #5 接入。 |
| #33 | 草稿含已登记提交、延期及移出项。审核绑定 MR 补丁。返工生成新草稿。MR 已合并且测试回写待核实时，终稿保留后续去向。 |
| #34 | 从 npm 正式 `0.2.1` 换装本机候选包，检查启动、重启和卸载。手工补充的档案入口与旧状态文件仍可读。以安装包宿主入口回归跨项目归档、重启、旧稿读取和索引重建。 |
