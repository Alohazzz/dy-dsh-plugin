# 云效议题插件第一版 Spec

2026-11-18 · 首版范围与开发约定已确认，实施与安装验收待完成

## 安装后要验证的结果

开发人员把本地插件包装入 DSH Web profile 后，能从侧栏进入「云效议题」，用一条真实测试议题完成筛选、开工、返回会话、预览并回写评论、流转并核对状态。排期人员可以先把一条或多条议题加入交付计划，也可以让单个议题直接开工。回写评论与变更工作项状态分别由用户确认。

现有 Web 原型使用模拟数据，现有宿主命令已覆盖按编号读取、绑定、预览、发布与流转的部分逻辑。两者都是实施输入。首版交付以安装后的真实面板操作为验收入口。

## 用户流程与行为约定

| 环节 | 用户可见行为与结果 |
| --- | --- |
| 连接与项目 | 展示云效连接状态、组织和云效项目。支持刷新、重新连接。另选 DSH 目标开发工作区，用于计划和开工。切换项目后清理失效选项、选择集与旧详情；支持在「连接设置」维护 Token、组织 ID 和默认项目 ID。鉴权失败显示连接错误和设置入口。 |
| 议题池与详情（Y1） | 按类型、我负责的、状态、产品、版本、计划完成日期及编号或标题组合筛选。状态、产品和版本支持多选，日期支持本周、本月及自定义区间。支持清空筛选、分页加载、空结果和加载失败重试。行上展示编号、标题、类型、云效状态、产品、优先级、负责人、创建日、截止日及逾期提示。详情展示正文、附件和正文图片，提供云效原议题链接。 |
| 单选与多选（Y3 入口） | 单条提供「发起讨论」。勾选多条后显示数量及「发起讨论」「添加到计划」，保留勾选顺序。已占用项显示原因和已有去向。讨论入口仅展示目标工作区和议题清单，返回保留选择。批量讨论的执行流程由后续设计决定。 |
| 交付计划（P1 首批） | 在目标工作区创建计划，填写名称、源分支和计划完成日期。单条或多条加入当前项目进行中的计划。无候选时提示创建。提交前可核对目标计划、议题顺序及将变更的云效字段。成功后显示计划归属。 |
| 直接开工与会话（Y2） | 从议题行或详情开工，读取正文、显示图片及材料获取结果。可选目标工作区并填写补充。新建会话使用标准 Agent 和完全访问权限。需求支持直接执行或先澄清，澄清方式依据宿主可用能力；缺陷先诊断取证。原文失败时允许重试或补充后继续。确认前可取消，确认后绑定唯一会话。准备失败可以重试；再次点击或重开面板可返回已有会话。 |
| 回写交付结果（Y4） | 从绑定会话的 discussion.md 提取「修改方案汇总」「影响范围与测试」。原稿缺失或章节不完整时指出原因。用户可预览、编辑或重新生成，确认后分别发布为开发向、测试向评论。逐条显示回执与时间。部分失败保留成功项，结果不明确时先核对远端，避免重复发布。 |
| 状态流转（Y6） | 从云效读取当前状态及该工作项允许的目标。确认页显示议题、原状态与目标。提交后回查，按核实结果更新详情和当前筛选列表。回查超时保留上次核实状态并提供单独回查。回写评论成功后仍由用户决定是否完结。 |

### 加入与移出计划的字段规则

议题已处于「待开发」时，保留已有负责人和计划开始时间，空值分别补为云效当前用户和当天。其他符合条件的议题使用同样的默认值并流转到「待开发」。计划完成时间沿用云效已有值。若工作流要求填写计划完成时间且议题未填，使用所选交付计划的完成日期补填后重试流转。批量提交逐条显示成功、已加入、失败、未处理，重试仅处理可重试项。

从计划详情确认移出时，将议题回退到「已确认」并清空计划开始时间。负责人和计划完成时间保留。加入和移出都在云效回查成功后更新本地计划归属，目标状态不可达或云效写入失败时显示原因。

## 技术方向与数据归属

- 宿主插件采用 TypeScript，负责云效凭据、OpenAPI 调用、工作区和会话绑定、回写回执。浏览器面板通过宿主能力发起操作。凭据只在宿主侧使用。
- 面板采用 React + TypeScript，复用 DSH 的 React 实例、侧栏和主区域插槽，界面遵循 Design.md。建议优先采用原型的列表与详情分栏，窄屏可返回列表。
- 以 npm 组合包交付，通过 dsh.bundle 注册到 profile。首轮交付物包含本地可安装包、适配版本、配置项、安装与卸载说明。Desktop 内置运行时与独立 CLI 分别核对版本和支持能力。
- 云效负责工作项与评论的最终状态，DSH 负责工作区、Agent 与会话。计划归属和回执需跨面板刷新、宿主重启保留。议题按组织、项目和工作项 ID 识别，显示编号用于查询与展示。
- 沿用已有 /yunxiao 命令作为会话入口。面板与命令共享同一份绑定和回执，支持从任一入口继续。查询和写入逻辑集中在宿主，向面板返回结构化的操作结果。议题原文和 discussion.md 保存在开发工作区，计划归属、绑定与回执保存在 DSH 用户目录。

## 安装验收场景

| 场景 | 通过条件 |
| --- | --- |
| 安装与配置 | 在干净的 DSH Desktop Web profile 安装本地包，重启可见侧栏入口；未配置时显示配置指引，配置后能读取真实测试项目。卸载并重启后入口消失。 |
| 筛选与返回 | 按状态、产品和日期筛选后用编号定位测试议题，对照云效原页核对正文与附件。列表有多页时能读到后续页；刷新失败可重试。 |
| 讨论入口 | 按相反于列表的顺序勾选两条议题，打开讨论后所列顺序与勾选一致。关闭后勾选仍在，DSH 会话数量不变。 |
| 批量加计划 | 为同一工作区创建计划，选择一个已待开发和一个需要变更状态的测试项。对照云效原页核对字段。制造单项失败后可看到逐条结果，重试时成功项只出现一次。 |
| 移出计划 | 从计划详情确认移出测试议题，核对云效状态、计划开始和完成时间、负责人及本地计划归属。云效更新失败时议题仍在计划中，重试只补未完成的同步。 |
| 开工与恢复 | 从一条需求选择先澄清，从一条缺陷检查诊断入口。确认开工后核对工作区、Agent 与绑定议题。重开面板返回原会话，材料准备失败可原位重试。 |
| 重复开工 | 同一工作区从列表与命令同时对同一议题开工，只产生一个会话和一次派发。执行完成并重启宿主后，从详情再次开工，核对会话 ID、交付稿与回执均指向原记录。 |
| 回写与恢复 | 预览两段带有可区分内容的评论，编辑其中一段后确认。第二条失败时重启并重试，在原议题核对最终恰有两条及其正文、回执。 |
| 流转与回查 | 在状态筛选下推进测试议题，核对云效原页与列表。模拟提交成功但回查超时，再次回查后只刷新状态；已不符合筛选的议题移出列表。 |

## 已确认的开发约定

1. 在 DSH Desktop 验收安装、重启加载、卸载和议题闭环。独立 DSH Web 用于开发调试。交付时记录实际验证的 Desktop 与内置运行时版本。
2. 交付计划记录源分支，支持创建计划、单条和批量加入、移出和云效字段同步。
3. 云效凭据优先从 DSH 本机凭据存储读取，保留宿主环境变量作为回退。面板支持测试、保存、更换和清除本地设置，状态响应仅包含令牌配置状态。
4. 同一 DSH 工作区内，同一云效议题始终定位到首次开工绑定的会话。执行完成后仍可返回补充交付稿或查看回执。列表、详情、命令复用同一查找与绑定逻辑，重复请求只派发一次执行任务。
5. 自动测试覆盖并发重复开工、批量加计划部分失败、评论补发及状态回查超时。安装包随附版本号、配置、安装与卸载说明。

后续独立议题包括批量讨论执行与依赖调度、价值评分、补录新议题、Codeup 合并和公司技能仓库管理。公司技能仓库的绑定、读取及按项目或 Agent 加载仍保留为必迁要求。

## 交付计划与合并请求

工作台沿用 DSH 的顶部模块导航和主题变量。交付计划使用筛选表格和详情页。分支配置、发起和关联沿用插件原生对话框，发起流程复用单仓 Git 预览和确认。窄容器内表格独立横向滚动。

交付计划详情页在标题旁显示交付状态，标题下显示完成日、项目和工作区。交付分支区并列展示源分支和目标分支，仓库、基础分支和代码目录放在其下。该区域复用工作台主按钮，按当前状态突出配置分支、关联或发起 MR、查看已关联 MR。计划议题区在标题旁显示数量，空状态保留表头。

旧计划保留源分支和议题成员，进入详情后补齐一个 Codeup 仓库和目标分支。配置校验所选仓库的本地源分支及远端目标分支。发起时再校验当前检出、提交和 origin。存在精确匹配的开放 MR 时，用户可选中并关联。

关联随本地计划保存。MR 使用 Codeup 仓库 ID 与仓库内编号定位。计划和待审队列打开同一个详情组件，并各自保留返回入口。计划刷新时通过 Codeup 回查合并状态。待审队列显示由当前用户评审且本人尚未评审的请求。人工批准和合并继续在 Codeup 完成。
