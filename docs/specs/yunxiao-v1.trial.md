# 云效议题插件第一版 Spec

2026-11-18 · 首版范围与开发约定已确认，实施与安装验收待完成

## 安装后要验证的结果

开发人员将本地插件包装入 DSH Web profile，从侧栏进入「云效议题」，用一条真实测试议题完成筛选、开工、返回会话、预览并回写评论、流转和状态核对。排期人员可将单条或多条议题加入交付计划，也可让单条议题直接开工。评论回写与状态变更由用户分别确认。

实施参考两项：使用模拟数据的 Web 原型，以及覆盖部分按编号读取、绑定、预览、发布和流转逻辑的宿主命令。首版以安装后的真实面板操作验收。

## 用户流程与行为约定

| 环节 | 用户可见行为与结果 |
| --- | --- |
| 连接与项目 | 显示云效连接状态、组织和项目，可刷新或重连。另选 DSH 开发工作区用于计划和开工。切换项目清理失效选项、选择集和旧详情。「连接设置」可维护 Token、组织 ID 和默认项目 ID。鉴权失败时显示连接错误和设置入口。 |
| 议题池与详情（Y1） | 按类型、「我负责的」、状态、产品、版本、计划完成日期及编号或标题组合筛选。状态、产品、版本可多选。日期可选本周、本月或自定义区间。支持清空筛选、分页、空结果和加载失败重试。列表行显示编号、标题、类型、云效状态、产品、优先级、负责人、创建日、截止日及逾期提示。详情显示正文、附件、正文图片及云效原议题链接。 |
| 单选与多选（Y3 入口） | 单条提供「发起讨论」。勾选多条后显示数量及「发起讨论」「添加到计划」，保留勾选顺序。已占用项显示原因和已有去向。讨论入口仅显示目标工作区和议题清单，返回时保留选择。批量讨论的执行流程留到后续设计。 |
| 交付计划（P1 首批） | 在目标工作区创建计划，填写名称、源分支和计划完成日期。可将单条或多条议题加入当前项目进行中的计划。无候选计划时提示创建。提交前可核对目标计划、议题顺序和待变更的云效字段。成功后显示计划归属。 |
| 直接开工与会话（Y2） | 从议题行或详情开工，读取正文，显示图片和材料获取结果。可选目标工作区并填写补充。新建会话使用标准 Agent 和完全访问权限。需求可直接执行或先澄清，澄清方式取决于宿主能力。缺陷先诊断取证。原文获取失败时可重试或补充后继续。确认前可取消，确认后绑定唯一会话。准备失败可重试，再次点击或重开面板可返回已有会话。 |
| 回写交付结果（Y4） | 从绑定会话的 discussion.md 提取「修改方案汇总」「影响范围与测试」。原稿缺失或章节不完整时说明原因。用户可预览、编辑或重新生成，确认后分别发布开发向、测试向评论，逐条显示回执和时间。部分失败时保留成功项。结果不明确时先核对远端，避免重复发布。 |
| 状态流转（Y6） | 从云效读取工作项当前状态和可选目标。确认页显示议题、原状态、目标。提交后按回查结果更新详情和当前筛选列表。回查超时保留上次核实状态，可单独回查。评论回写成功后仍由用户决定是否完结。 |

### 加入与移出计划的字段规则

- **加入计划**。已「待开发」的议题保留负责人和计划开始时间，空值分别补为云效当前用户、当天。其他符合条件的议题使用相同默认值，流转到「待开发」。计划完成时间沿用云效已有值。若工作流要求填写且计划完成时间为空，按所选交付计划的完成日期补填，再重试流转。批量提交逐条显示成功、已加入、失败、未处理，仅重试可重试项。
- **移出计划**。从计划详情确认移出后，回退到「已确认」，清空计划开始时间，保留负责人和计划完成时间。
- **同步结果**。加入和移出均在云效回查成功后更新本地计划归属。目标状态不可达或云效写入失败时显示原因。

## 技术方向与数据归属

- TypeScript 宿主插件负责云效凭据、OpenAPI 查询和写入、工作区与会话绑定、回写回执。面板调用宿主并接收结构化结果。凭据仅在宿主使用。
- React + TypeScript 面板复用 DSH 的 React 实例、侧栏和主区域插槽，遵循 Design.md。建议优先沿用原型的列表与详情分栏，窄屏可返回列表。
- 通过 dsh.bundle 将 npm 组合包注册到 profile。首轮交付本地可安装包、版本号、适配版本、配置项和安装卸载说明。分别核对 Desktop 内置运行时和独立 CLI 的版本与能力。
- 云效负责工作项与评论的最终状态，DSH 负责工作区、Agent 和会话。议题按组织、项目和工作项 ID 识别，显示编号用于查询和展示。
- /yunxiao 仍为会话入口，与面板共用绑定和回执，可从任一入口继续。开发工作区保存议题原文和 discussion.md。DSH 用户目录保存计划归属、绑定和回执。计划归属和回执须经面板刷新和宿主重启后保留。

## 安装验收场景

| 场景 | 通过条件 |
| --- | --- |
| 安装与配置 | 在干净的 DSH Desktop Web profile 安装本地包，重启后显示侧栏入口。未配置时显示指引，配置后可读取真实测试项目。卸载并重启后入口消失。 |
| 筛选与返回 | 按状态、产品和日期筛选，再用编号定位测试议题。对照云效原页核对正文和附件。有多页时可读取后续页，刷新失败可重试。 |
| 讨论入口 | 按与列表相反的顺序勾选两条议题。讨论清单与勾选顺序一致，关闭后保留勾选，DSH 会话数不变。 |
| 批量加计划 | 为同一工作区创建计划，选择一个已待开发和一个须变更状态的测试项，对照云效原页核对字段。制造单项失败，检查逐条结果。重试时成功项只出现一次。 |
| 移出计划 | 从计划详情确认移出测试议题，核对云效状态、计划开始和完成时间、负责人和本地计划归属。云效更新失败时议题留在计划中，重试仅补未完成的同步。 |
| 开工与恢复 | 为一条需求选择先澄清，为一条缺陷检查诊断入口。确认开工后核对工作区、Agent 和绑定议题。重开面板返回原会话，材料准备失败可原位重试。 |
| 重复开工 | 同一工作区内，列表与命令同时对同一议题开工，仅创建一个会话、派发一次。执行完成并重启宿主后，从详情再次开工，核对会话 ID、交付稿和回执均指向原记录。 |
| 回写与恢复 | 预览两段可区分的评论，编辑其中一段后确认。第二条失败时重启并重试。在原议题核对最终恰有两条评论，并核对正文和回执。 |
| 流转与回查 | 在状态筛选下推进测试议题，核对云效原页和列表。模拟提交成功、回查超时。再次回查只刷新状态，议题不再符合筛选时移出列表。 |

## 已确认的开发约定

1. 在 DSH Desktop 验收安装、重启加载、卸载和议题闭环。用独立 DSH Web 调试。交付时记录实测 Desktop 和内置运行时版本。
2. 交付计划的首批能力与字段同步见「用户流程与行为约定」。
3. 云效凭据优先读取 DSH 本机凭据存储，回退到宿主环境变量。面板支持测试、保存、更换和清除本地设置，状态响应仅返回令牌配置状态。
4. 同一 DSH 工作区内，同一云效议题始终定位至首次开工绑定的会话。执行完成后仍可补充交付稿或查看回执。列表、详情和命令共用查找与绑定逻辑，重复请求仅派发一次执行任务。
5. 自动测试覆盖并发重复开工、批量加计划部分失败、评论补发和状态回查超时。安装包随附材料见「技术方向与数据归属」。

后续独立议题包括批量讨论执行与依赖调度、价值评分、补录新议题、Codeup 合并和公司技能仓库管理。公司技能仓库的绑定、读取及按项目或 Agent 加载仍须迁移。

## 交付计划与合并请求

工作台沿用 DSH 顶部模块导航和主题变量。交付计划采用筛选表格和详情页。配置分支、发起和关联 MR 沿用插件原生对话框。发起 MR 复用单仓 Git 预览和确认。窄容器内表格独立横向滚动。

计划详情在标题旁显示交付状态，标题下显示完成日、项目和工作区。交付分支区并列显示源分支和目标分支，下方显示仓库、基础分支和代码目录。该区复用工作台主按钮，按状态突出配置分支、关联或发起 MR、查看已关联 MR。计划议题区在标题旁显示数量，空状态保留表头。

旧计划保留源分支和议题成员，进入详情后补齐一个 Codeup 仓库和目标分支。配置时校验所选仓库的本地源分支和远端目标分支。发起时再校验当前检出、提交和 origin。若有精确匹配的开放 MR，用户可选中并关联。

关联随本地计划保存。MR 按 Codeup 仓库 ID 和仓库内编号定位。计划和待审队列共用详情组件，各自保留返回入口。刷新计划时向 Codeup 回查合并状态。待审队列显示由当前用户评审且本人尚未评审的请求。人工批准和合并仍在 Codeup 完成。
