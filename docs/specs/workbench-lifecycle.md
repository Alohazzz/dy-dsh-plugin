# 研发工作台生命周期与档案契约

本契约细化研发工作台的阶段、归档身份与兼容读取规则，供文档校验、项目建档和后续工作流接入使用。[需求文档](workbench-requirements.md) · [实施计划](workbench-implementation-plan.md)

## 议题阶段

每次参与计划单独记录阶段。同一计划内，各议题按自己的证据推进。首次归档从「调研」开始。旧材料只能证明部分进度时，记录已证实的阶段与待核实项。

| 阶段 | 触发动作与依据 | 产物 | 后续路径 |
| --- | --- | --- | --- |
| 调研 | 议题成功加入计划，核对各项条件的可行性。补足影响方案的证据，并集中确认关键技术取舍。 | 调研报告和确认记录。关键问题解决后，按已确认结论生成可独立引用的执行方案草稿。 | 用户指定草稿送审后进入待审核。 |
| 待审核 | 送审指定版本，冻结送审正文。 | 送审快照，审核人、时间、意见与结论。 | 补事实时退回调研。仅调整方案时可形成新版本重新送审。批准指定版本后进入定稿。 |
| 定稿 | 指定版本通过审核，确认它仍是本次待审版本。 | 指向获批快照的记录。 | 核对成员资格、计划检出及当前获批版本，派发成功后进入执行。修改范围或验收标准时重新送审。 |
| 执行 | 派发获批方案，按同一请求标识重试未完成的派发。 | 执行绑定、执行小结及用户确认。分别记录已派发、已生成小结、已确认。 | 发现范围或验收变化时重新送审，保留此前依据和小结。确认小结并核实实际提交后进入提交。 |
| 提交 | 核实实际仓库和提交 SHA，建立逐议题关联。 | 变更记录及相关执行小结引用。云效回写保存最终确认正文与逐项回执。 | 返工按变更范围回到执行或重新送审，保存历史提交与回执。 |

移出和延期作为计划成员事件保存。移出结束本次参与，后台结果仍归属原参与记录。延期保留成员身份和当前阶段。

## 计划阶段

| 阶段 | 触发动作与依据 | 产物 | 后续路径 |
| --- | --- | --- | --- |
| 创建 | 稳定工作区、交付仓库与分支已确定，宿主成功保存计划。 | 计划目标、计划完成日期、初始成员和范围变动记录。 | 成功发起或关联 MR 后进入提交合并。 |
| 提交合并 | 核对参与议题、实际提交与目标分支，记录 MR 引用。 | 计划完成报告草稿，列明原定范围、变动、交付与未决项。 | 提交指定报告版本与对应 MR 版本后进入审核。 |
| 审核 | 审核人审阅报告草稿、提交和验收证据。 | 审核人、时间、意见、结论及对应报告版本和 MR 补丁或提交。 | 返工回到提交合并，更新草稿后复审。确认交付并核对远端结果后可关闭。 |
| 关闭 | 用户明确关闭计划，已核对 MR、回写和成员结果，遗留事项均有去向。 | 计划完成报告终稿及关闭记录。远端结果缺少证据时标记待核实。 | 后续计划通过归档引用终稿。 |

归档独立保存三类状态。计划或议题阶段来自本地动作及其证据。云效状态保存工作项状态 ID、显示名称和回查时间。Codeup MR 结果保存仓库 ID、MR 编号、远端状态和回查时间。例如 MR 已合并时，计划仍可处于审核，测试向评论仍可待补发。

## 标识、版本与归档清单

归档根位于创建计划时选定的稳定工作区 `docs/workbench/`。宿主把工作区身份、云效组织 ID、云效项目 ID、计划 ID 绑定到后台任务的启动上下文。独立检出通过计划绑定回到稳定工作区。新目录使用项目名、计划名或议题编号加短标识，清单保留原始 ID。展示名称变化后沿用已分配的目录，旧档案沿用原路径和文件名。

| 层级 | 文件 | 必需信息 |
| --- | --- | --- |
| 工作区 | `README.md`、`manifest.json` | 查档入口、档案格式版本、脚手架版本。 |
| 云效项目 | `<项目目录>/index.json` | 以计划及议题清单重建，索引计划、议题编号、模块、关键词和替代关系。 |
| 计划 | `plans/<计划ID>/plan.json` | 计划身份、目标、仓库与分支、阶段、初始成员、发生时间及原因、MR、报告版本和遗留项。 |
| 议题 | `issues/<工作项ID>/issue.json` | 工作项身份、展示编号、模块、参与记录、阶段、文档及替代关系。每次成功加入分配一个参与标识，移出后保留旧记录。 |

正式文档与历史快照通过清单引用。每个快照记录类型、文档版本、模板版本、参与标识（适用时）、来源及创建时间。每种文档的版本在所属计划或议题目录中递增，同一工作项在同一计划内再次加入时继续分配新版本。批准、执行、提交及发布分别引用确切的快照或远端记录。返工时追加快照。写入按事件标识去重，索引从已提交的清单恢复。

执行绑定按「工作区、组织、项目、计划、工作项、参与标识、执行尝试」区分。相同参与记录、相同获批版本及同一尝试的重试复用原会话和请求。重新获批后开始新的执行尝试，并链接旧尝试。调研会话仅在同一次参与内用于修订，跨参与时可查阅旧报告和方案。运行中的会话和凭据留在宿主存储，档案保存可授权访问的证据引用。

## 兼容样例

| 样例 | 核对结果 |
| --- | --- |
| 旧计划只有成员清单和定稿版本。 | 原成员清单作为当前范围。初始范围和变动时间待核实。有版本及归属证据时保留定稿引用并标记审核人及意见待核实。能从原任务清单核实派发时保留执行引用。已有交付稿和回执按原格式读取。 |
| 计划内 A 已获批 v2 并执行，B 的 v1 被退回。 | A 保持执行，绑定指向 A 的 v2。B 补调研后以 v2 重新送审，原退回仍指向 B 的 v1。两项分别保留云效状态，共享计划关联的 MR 引用。 |
| A 从 P1 移出后重入 P1，或转入 P2。 | 新参与各自从调研开始。P1 旧快照、提交和回执保持原归属，新方案可引用旧证据。晚到结果按原任务绑定写回。旧绑定只有工作项键时，需核对绑定或任务清单中的计划 ID 后才关联旧参与，归属不明时标记待核实。 |
| MR 已合并，测试评论发布失败。 | MR 保存已合并及回查证据，回写记录测试待补发。计划关闭时记录遗留事项及去向。 |

当前实现以稳定工作区与工作项定位执行会话，调研批次以工作区 ID 和计划定位。接入本契约时，旧绑定可用于兼容读取及原请求重试，新派发按参与记录和获批版本查找。旧版定稿用 `finalizedVersion` 核对草稿序号，旧任务清单用 `planId` 和 `planVersion` 核对归属。
